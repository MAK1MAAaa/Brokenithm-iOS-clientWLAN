# 协议与实现

## 连接与发现

PC 主动连接 iPad 公布的 TCP 服务。Brokenithm-SwiftUI 通常监听 TCP 24864，Bonjour 服务类型为 `_brokenithm._tcp.local`。

发现流程为 PTR → 服务实例 SRV → 目标主机 A/AAAA。使用活动 IPv4 网卡的 mDNS 组播 `224.0.0.251:5353`，支持压缩名称、跨报文补全、TTL、离线通知及网卡隔离。从应答解析 IPv4 和 IPv6 地址，IPv6 link-local 地址包含正确 scope。纯 IPv6 网络可使用手动 IP。

同一查询的发送间隔至少一秒。每轮完整收集发现结果，避免先回应的其他设备遮蔽目标。UDP 5353 被独占时会尝试临时端口的旧式 mDNS 查询与单播应答。

候选地址按稳定顺序尝试，优先 IPv4；一个地址失败后继续后续地址。首次握手成功后，当前运行保持同一服务实例，断线重新发现。更换设备或实例名称改变时可重启接收端。

参考：[RFC 6762](https://www.rfc-editor.org/rfc/rfc6762.html)、[RFC 6763](https://www.rfc-editor.org/rfc/rfc6763.html)。

## TCP 帧

每帧以一个字节表示后续负载长度。读取按长度累积，支持分片和粘包；连接成功后先校验 iPad 发来的 WEL。

| 帧 | 负载长度 | 负载内容 |
| --- | --- | --- |
| WEL | 3 | `WEL` |
| INP | 41–45 | `INP` + AIR 6 字节 + slider 32 字节 + 可选 test/service/coin/card |
| AIR | 4 | `AIR` + 0/1 |
| FNC | 4 | `FNC` + 1（投币）或 2（刷卡） |
| LED | 99 | `LED` + RGB 96 字节，含长度前缀共 100 字节 |

收到长度前缀后，单次后续读取停滞超过两秒时断开重连。等待下一帧首字节没有应用层空闲超时，避免静默长按被误释放。TCP keepalive 帮助发现网络中断，具体发现时间由系统 TCP 栈决定。

LED 每次以完整的 100 字节帧写入，最多每 10 毫秒检查变化，未变化时每 500 毫秒刷新。一次写入不能保证远端一次 TCP receive 收到完整帧。

## 共享内存

映射名称为 `Local\BROKENITHM_SHARED_BUFFER`。创建容量 1024 字节，仅打开所需的 150 字节视图，兼容游戏驱动先创建的较小映射。

| 偏移 | 用途 |
| --- | --- |
| 0–5 | AIR |
| 6–37 | slider |
| 38–133 | 游戏写入的 LED RGB |
| 134–137 | test / service / coin / card |
| 138–149 | 驱动的远程卡字段，本接收端不写入 |

投币和刷卡只写入一个字节；关闭 AIR 时立即清空六个传感器字节。断线或正常退出会清空输入和四个功能字节，保留 LED 与远程卡区域。

## 输出模式

普通模式不创建文件日志，仅在有效 WEL 握手后通过独立输出线程显示成功通知。拒绝连接、错误握手和发现失败不会显示成功。

诊断模式使用独立文件与控制台线程，网络处理不等待输出 I/O。有限队列在极端积压时允许丢弃旧消息；序号间隙可用于识别积压。
